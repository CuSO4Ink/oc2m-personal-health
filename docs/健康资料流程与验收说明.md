# 健康资料流程与验收说明

## 页面怎样组织

| 入口 | 用途 |
|---|---|
| 首页 | 初次使用引导；之后优先展示待核对报告、指标提醒或个人待办 |
| 健康资料 → 报告与病历 | 医院同步、上传文件、全文查找、查看原件、核对识别内容、个人分类和备注 |
| 健康资料 → 个人健康信息 | 姓名、出生日期、联系电话、既往病史、家族病史、用药、过敏；可查看报告来源及修改历史 |
| 健康状况 | 需要关注、指标趋势、记录明细；手工补充指标、更正或作废已有记录 |
| 提醒与服务 | 我的提醒为默认页，医疗预约为模拟流程，养老服务为目录演示 |
| 共享与访问 | 明确选择资料和接收人，预览后授权；查看模拟接收方访问及本人／系统操作记录 |
| 病友交流 | 动态、圈子、好友与私聊；在账户设置中开启或关闭，不自动开放健康资料 |
| 右上角 | 消息通知、账户与安全、使用帮助 |

健康资料负责保存事实和原件，健康状况负责汇总已确认内容。两者通过来源链接相互连接，不再让健康史成为独立一级入口。页面说明可折叠、关闭，并记住当前账户的选择；右上角帮助可以恢复提示。

## 建议按这条流程测试

1. 用 `start@example.test` 登录空白账户。先在健康资料的个人健康信息中填写出生日期等已有基础信息。不明确的病史可以保留“不确定”，不必全部填完。
2. 回到报告与病历，点击医院同步、查看可同步的资料，再确认同步。8 份合成 PDF 覆盖检验、门诊、用药、过敏、影像、护理六类；3 份检验报告提供不同日期的指标，护理文件为纯扫描 PDF。
3. 同步后查看各文件的识别状态。此时原件与文字索引已保存，但尚未新增指标或健康史。再同步相同样本不会重复新增。
4. 搜索标题、疾病或 PDF 原文片段。例如 `thyroid` 命中影像报告，`Achilles` 命中扫描护理记录。结果显示文件、命中摘要和页码，可进入对应原件页面。再试日期、疾病和记录类型筛选。
5. 打开“待核对信息”，对照原件勾选指标，核对数值、单位、完整测量时间、测量场景。只预填原文明确标记的时间；没有时间的候选需要补全。也可批量选择并统一设置确实属于同一测量时刻的时间。
6. 在同一核对框的健康史页签确认明确记载的疾病、亲属关系、用药或过敏。不确定、否定及待排描述不会作为确诊导入。手填的同名条目不会被报告内容覆盖，可关联报告来源。
7. 确认后，个人健康信息显示来源；健康状况显示对应指标。模拟报告日期固定在 2026 年 6、7、9 月，测试完整三点趋势时选“1 年”（测试时间须覆盖这些日期）。默认 30 天仅显示近期数据，不会篡改日期让趋势显得更完整。
8. 健康关注按血压、血糖、心率主题合并适用的病史、家族史和近期指标，展开“依据与来源”能回看报告。缺少年龄、特殊情境或不适用成人参考时，系统说明原因，不强行给出结论。
9. 新建共享，选择接收人、期限及具体范围：记录文字、完整原文件、指定健康信息、指定指标。预览实际内容后授权。模拟接收方查看原件，再撤销授权，验证再次访问被拒绝；访问记录可核对处理。
10. 用 Alex 与 Jamie 两个账户、两个浏览器会话测试加好友、接受申请、私聊。好友关系不等于健康资料授权，匿名帖子不提供身份联系入口。

本地上传 PDF／图片使用相同整理流程。指标也始终允许手工录入；更正和作废保留历史及来源。

## 实现边界

- **医院与医生端**：没有真实医院接口，也没有独立医生登录端。医院同步使用仓库内真实合成 PDF；接收方演示由本人发起，但其读取仍经过真实的对象范围、期限、撤销及隐私校验。
- **全文与识别**：文本 PDF 优先直接提取文字；扫描页使用本机 Windows OCR。全文逐页保存，与可共享正文分离。最多处理 200 页，扫描页按 5 页分批，每批超时 35 秒，总处理约 110 秒后停止并明确显示部分完成。失败页不能被宣称可全文查找；原件保留，可重试或拆分。无 Windows OCR 的环境仍可处理文本 PDF，扫描件需要另装合适的识别能力或手工录入。
- **候选范围**：核对草稿最多 60,000 字符，最多 30 个明确健康史候选。支持有明确标签、数值及单位的血压、血糖、心率，以及限定标签格式的健康史。它不是通用医学文档理解，也不能保证 OCR 没有错字。全文搜索范围与候选识别范围分别显示。
- **健康关注**：使用已确认资料和现有有限规则，保留规则版本及来源。确认的医院诊断可以参与健康史匹配；不会从药名推断疾病，不做药物相互作用检查，不诊断、不推荐调整药物。
- **共享**：新授权固定所选内容和版本，之后新增数据不会自动扩容。旧授权保持原语义。完整原件必须单独选择并确认；隐藏文字字段不会给 PDF 打码，存在字段隐私遮盖的档案不能直接共享完整原件。受控原件读取还核对原件哈希、归属、归档及删除状态。
- **只读和下载**：接收方只读。关闭下载权限会关闭本站导出接口，但预览过的内容不能提供 DRM 式禁止截图或另存的保证；撤销授权阻止后续访问，不能收回已导出的文件。
- **审计**：同步、分类、索引、核对、授权、原件访问等保留记录。本人、系统和本地模拟接收方明确区分；没有真实地理定位。共享访问被阻止会进入访问页及站内待核对通知。
- **社区及服务**：真实站内好友、文字私聊和社区操作会持久保存；举报处理仍为标记清楚的模拟流程。预约没有通知真实医院，邮件、短信、设备推送和支付没有连接。

## 干净的演示数据

在仓库的两个终端分别运行：

```powershell
cd backend
.\.venv\Scripts\python.exe run_demo.py --fresh
```

```powershell
cd frontend
npm.cmd run dev
```

打开 `http://127.0.0.1:5173`，后端为 `5001`。下次想继续同一演示库时去掉 `--fresh`。

| 账户 | 密码 | 场景 |
|---|---|---|
| start@example.test | HealthDemo2026! | 零资料、零指标，从同步开始 |
| alex@example.test | HealthDemo2026! | 少量资料、近期指标和报告待核对 |
| jamie@example.test | HealthDemo2026! | 第二位社区用户，便于测试好友与私聊 |

`--fresh` 创建新文件并保留旧演示库；不会清空 `personal_health.db` 或其他真实库。本轮使用独立验收数据库，交付演示库已另行准备为 `demo-20260928-061227-834405.db`，`current.json` 已指向它。直接运行 `run_demo.py` 即可继续这套干净数据；加 `--fresh` 则另建一套。只读检查确认：空白账户零资料、零指标，Alex 有 2 条资料、7 条指标和 3 个未确认候选；所有账户均无测试遗留授权、通知或指标警报。数据库版本为 4，仅增加表；旧 SQLite 缺少新表时先生成可恢复备份再升级。

## 验证结果

- 后端全量回归：103 项通过，包括原有账户隔离、并发、好友私聊及本轮文档索引、联合确认、固定共享范围、版本 3 到 4 的保留数据升级。
- 前端全量回归：10 个文件、26 项全部通过，无未处理异常。ESLint 静态检查与 Vite 生产构建通过。
- 真实浏览器：8 份 PDF 同步、全文命中摘要和页码、扫描 PDF 的本地 OCR、个人分类调整、6 份待核对报告确认后产生 9 条指标和 4 条健康资料、清空待核对列表、来源回查、三日期趋势均通过。
- 真实浏览器：混合范围授权、原件预览与下载、撤销后拒绝访问、访问记录，以及两个账户申请／接受好友并收发真实站内消息通过。
- 390px 手机布局：报告列表、文件预览、同步面板，以及首页、个人健康信息、健康状况、趋势、上传、服务、共享、通知和账户页均未出现页面横向溢出；私聊弹窗已实测。
- 验收运行于独立数据库和 5011／5183 等测试端口，没有重置已有个人数据库。代码修改未提交或推送。
- 构建仍提示一个约 698 kB 的共享依赖包超过推荐体积；功能构建成功，本轮未为消除提示升级组件库或大改打包架构。
