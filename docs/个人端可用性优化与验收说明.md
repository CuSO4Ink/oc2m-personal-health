# 个人端可用性优化与验收说明

本轮围绕“保存报告 → 核对读数 → 查看趋势 → 回查来源”整理个人端。界面仍以英文为主；外部医院、医生和预约保持明确的演示边界。此前档案权限、审计和社区数据能力继续保留。

## 启动与演示账号

安装依赖后，在仓库根目录打开两个 PowerShell 终端：

```powershell
# 终端一：独立演示后端，端口 5001
cd backend
.\.venv\Scripts\python.exe run_demo.py --fresh
```

```powershell
# 终端二：前端，默认端口 5173
cd frontend
npm.cmd run dev
```

访问 `http://127.0.0.1:5173`。下次继续演示时运行 `run_demo.py`，不带 `--fresh`。加上该参数会在 `backend/instance/usability-demo/` 新建数据库并更新当前指针，保留旧文件，不重置真实的 `personal_health.db`。个人业务环境仍用 `run.py` 和自己的配置。

| 账号 | 用途 |
|---|---|
| `start@example.test` | 空账号：检查首次使用引导和第一个报告流程。 |
| `alex@example.test` | 少量合成档案、指标、示例 PDF 和健康资料。 |
| `jamie@example.test` | 在另一个浏览器登录，验证好友确认及真实双账号私信。 |

三个演示账号密码均为 `HealthDemo2026!`。登录页选账号只填入表单，仍需点击 Sign In。新演示库没有堆积的历史待办；样本内容不代表真实患者。切换到新演示库时，页面帮助关闭状态和首次引导也会重新开始。

## 导航与日常入口

主导航按个人任务分成 Home、Health Records、Trends & Readings、Reminders & Care，以及 Sharing & Access 和可选 Community。账号与安全放在右上角，通知保留独立入口；移动端用抽屉菜单。帮助按钮解释基本流程，可重新显示已关闭的页面提示。

- Home 将一个可执行的下一步放在前面。新用户可逐步上传报告、记录读数、填写健康史，也可跳过。最近读数和更多统计按需查看，空数据不显示成健康结论。
- Health Records 集中管理文档；Health history 管理结构化既往史、家族史、用药、过敏。文档和健康史可互相切换。高级筛选、档案来源、隐私设置和个人备注默认收起；需要时展开。
- Trends & Readings 分为趋势、读数历史、提醒与健康关注点。提醒可定位相关读数；读数可设置测量提醒或回查报告来源。
- Reminders & Care 优先呈现个人提醒，预约仍标为演示。Sharing & Access 保留本人内容预览、授权、到期/撤销和访问历史。

## 报告与指标闭环

1. 在 Home / Health Records 点击 Upload a report。选 PDF、PNG 或 JPEG，核对报告名称和日期后保存。可下载合成示例 PDF 试用。若附件失败，已经建立的档案保留，支持重试或稍后继续。
2. 保存后打开审阅窗口；用户点击提取才开始。已有档案可在附件旁点 Extract readings，也可从档案正文寻找候选。
3. 逐项勾选需要的候选，核对或修改值及单位，填写测量日期时间、血糖空腹/餐后/随机等上下文。日期不从文件名或上传时间猜测，候选默认全部不勾选。
4. 勾选核对确认后才写入 HealthMeasurement。原始提取文本、校对文本、候选值、确认值、档案和附件来源保留；血糖 `mg/dL` 明示除以 18 转为 `mmol/L`，保留原始单位。
5. 导入结果直接链接到 Trends & Readings 的具体读数。在 Reading history 点击 View source report 回到来源及确认记录；之后更正读数也可追溯初始来源。同一来源候选重复导入会被跳过，并发请求不会重复写入。超过一年以前的报告也能直接回看；超出图表期间的目标读数单独显示，不混入当前期间的统计。

提取草稿与健康指标分开保存。提取或重新解析不会自动新增指标；版本冲突时保留当前草稿并阻止继续提交，用户明确重载后才能继续。

### 本地提取的实际范围

| 项目 | 实现及限制 |
|---|---|
| 文本 PDF | 使用 `pypdf` 实际读取文字。 |
| 图片与扫描 PDF | Windows 原生 WinRT OCR；扫描页由 Windows PDF API 渲染后识别。无云服务、无大模型调用。 |
| 语言 | 使用服务器已安装的 OCR 语言；当前本机可选英文与简体中文。中文字间距、小数及表格仍可能被错读，不保证直接产生正确候选。 |
| 支持指标 | 明确标签邻近明确单位的血压 `mmHg`、血糖 `mmol/L` / `mg/dL`、心率 `bpm` / `次/分`；英文及常见中文标签。 |
| 数量与资源 | 每条档案最多 10 个附件，每个 10 MB；每次提取最多前 5 页、60,000 字符、50 个候选；OCR 最长 35 秒。 |
| 未识别内容 | 页面说明失败及未处理页数。无 OCR、加密/不可读 PDF、无匹配候选或错读时，可换清晰文件、拆分报告，或粘贴/校对原文再找候选。不会伪造结果。 |

不自动导入参考范围、无标签或无单位的数字。未实现复杂表格理解、手写保证、任意检验项目和自动诊断。跨平台环境没有 Windows OCR 时，文本 PDF 和手工文本流程仍可用。

## 健康史与社区

健康史首页先显示四类摘要，点击单类编辑，减少一次出现大量表单。每类明确区分 Unknown / not recorded、None known、Add entries。当前修订号控制保存，冲突不覆盖较新内容；修订历史可查看以前保存的快照，仅本人可见。结构化健康史不自动加入档案共享或社区帖子。

社区主界面集中为动态、圈子、Friends & messages；昵称和隐私设置、举报及屏蔽管理放到对应抽屉。新账号可在右上角 Account & Security → Community preferences 打开社区；Alex 和 Jamie 已开启。添加好友可使用邀请码或用户自愿公开的昵称；收到申请者确认后才能私聊。匿名帖子不提供识别作者的联系入口，健康档案不自动进入社交内容。

两账号私信真实持久化并轮询更新，没有自动机器人回复。关闭社区会隐藏入口并停止社交操作和红点；已有圈子及确认的好友关系保留，待处理邀请取消。重新开启不补发旧红点。页面说明禁止诊断、处方和骚扰，举报及处理状态可查看；演示处理不等于存在真人运营审核。

## 边界与验收路径

本地账号、档案、资料、指标、授权检查、提醒及双用户社区使用真实数据库流程。医院同步、医生收件人访问、预约、举报处理等外部结果仍为明确标记的模拟；未连接真实医护系统、短信、人脸、支付和外部推送。

健康解读使用有限、可解释的参考规则；年龄未知、未成年人或特殊上下文停止一般成人解释。不诊断、不开药、不输出临床风险概率。本地保存不等于端到端加密，下载出的文件无法远程撤回。

验收建议按以下顺序走一遍：

1. 用 start 空账号上传示例报告，确认保存附件后尚无新增指标；提取后仍无新增指标。
2. 只选一条候选，修改数值，填写时间及上下文后确认；在趋势和来源窗口核对修改前后值。重提取同文件确认去重。
3. 换图片/扫描 PDF 验证本机 OCR；用无匹配文本或不清晰文件验证错误说明和粘贴原文回退。
4. 保存一类健康史并查看修订；两窗口编辑同一档案或资料，检查冲突保留草稿且不能覆盖新版本。
5. Alex 与 Jamie 分别登录两个独立浏览器会话，走完好友申请、接受、私信、屏蔽和关闭社区。
6. 在窄屏检查导航、上传、审阅、健康史编辑和私聊；分别检查未登录及跨账号资源访问拒绝。

自动化入口为后端 `python -m pytest -q`，前端 `npm test`、`npm run lint`、`npm run build`。提取针对性检查位于 `backend/tests/test_extraction.py` 与 `frontend/src/ReportExtraction.test.jsx`。
