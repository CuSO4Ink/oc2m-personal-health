## 2. 实现边界

### 真实运行的个人端能力

账号、档案、附件、个人健康资料、指标、授权状态、审计、社区帖子与好友私信均真实写入本地数据库，有账号隔离及相应状态检查。私聊需双方同意，不能借匿名帖子反查账号身份，好友不会自动看到健康资料。

### 明确标注模拟的能力

- 医院及设备来源数据、医院导入返回内容、医生/健康管理师目录。
- 个人端内发起的“模拟收件人访问”。其权限校验、允许/拒绝结果和审计是真实执行的，但发起方不是外部医生。
- 本地纠错申请的“模拟机构回复”、举报的“模拟审核结果”。没有冒充实际医护或运营人员。
- 医疗服务预约及养老目录中的外部服务结果，不向真实机构发送订单。
- 开发环境的验证码预览，不发送邮件，也不证明邮箱所有权。

`DEMO_FEATURES_ENABLED=false` 关闭模拟导入、纠错回复、收件人访问和审核操作。`RESET_CODE_DELIVERY=disabled` 关闭开发验证码恢复/邮箱变更。生产配置拒绝示例密钥和这些开发模式；这仍不等于已完成正式部署。

### 不作虚假完成声明的能力

- 短信、人脸、真实邮件/设备推送、真实医院和设备连接尚未接入。
- 健康解释是有限参考规则，关注点目前覆盖明确的高血压/糖尿病历史与三类指标的重复参考标记；不推断自由文本病史、不输出诊断、处方或临床风险概率。年龄未知、未成年及不适用上下文不会套用一般成人结论；没有匹配结果不代表健康无风险。
- 社区没有自动机器人回复；举报模拟不代表完整内容审核或真实人工运营。
- 私信及健康数据没有端到端加密，SQLite 中的业务数据也未做额外加密。密码哈希、账号隔离和授权检查不能被称为端到端加密。
- 站内通知依靠请求及页面轮询，浏览器关闭后没有外部送达保证。
- 界面继续使用英语；已去掉保存后不生效的语言切换，没有宣称已实现双语。

### 分享与历史的具体约定

1. 授权的记录 ID 集合固定，新记录不会自动加入；已选记录按当前内容和隐私设置返回，更新可能影响未来所见内容。
2. 敏感记录、敏感字段、归档记录在访问时再次检查。解除敏感标记或恢复归档后，仍有效的旧授权可能重新允许访问；若需永久停止，应撤销授权。
3. 原始附件与结构化健康资料保持私有；模拟下载仅包含授权字段的 JSON。已下载副本无法远程收回。
4. 更正、作废、归档及当前资料删除保留必要历史，不偷偷覆盖或伪造旧内容。更正/作废指标及其旧提醒不再参与当前统计和待处理计数。
5. “已读通知”“已查看事件”“业务已完成”分别处理。提醒周期为固定 UTC 间隔，夏令时前后当地时间可能变化，界面已有说明。

## 4. 使用和升级

按 README 启动当前 `backend/` 与 `frontend/`，不要启动 `tmp/sketch`。第一次使用本轮新代码打开既有 SQLite 时，会先备份再新增附表；没有删除旧数据或改写已有表字段。

新注册用户从空资料开始；在 Account & Security 开启社区后，填写昵称，用另一账号的邀请码申请好友，对方接受即可私聊。演示数据可使用已有演示账号；重复运行 seed 不再重置已有密码或重新开启已关闭社区。

本轮代码和说明保留在工作区，未执行 Git 提交、推送或部署。
